# 게임 규칙을 정한 과정

## 만들고 싶은 경험

어두운 세계에서 한 번에 멀리 나아가기보다, 자원을 확보하고 길을 연결하며 활동 범위를 조금씩 넓히는 경험을 만들고자 했습니다. 어디까지 탐사할지, 어떤 길을 남길지, 파손된 길을 수리할지 회수할지를 플레이어가 선택하도록 구성했습니다.

아래는 전체 게임의 완성도를 평가한 글이 아니라, 제가 정한 두 가지 자원 규칙과 현재 코드에 반영된 범위를 설명한 기록입니다.

## 1. 재료 보충을 고정 개수가 아닌 부족분 기준으로 변경

### 의도와 선택

탐사를 이어 가려면 길 재료를 다시 확보할 기회가 필요했습니다. 초기 논의의 하루 한 개 보충 방식 대신, 매일 권역별 설정 수량을 기준으로 부족분을 채우도록 요청했습니다. 전날 많이 모은 권역에는 그만큼 많이 보충되도록 한 선택입니다.

### 반영된 처리

[RefreshResourcesForNight](../src/game_core.cpp)는 새 밤의 자원을 갱신하면서 권역별 활성 재료 수량을 계산합니다. 설정 상한에 못 미치면 같은 권역의 유효한 후보 위치에 재료를 추가합니다. 지형과 다른 자원 등의 점유 조건을 검사하며, 이전 위치와 다른 후보를 우선 선택합니다. 다른 후보가 없으면 이전 위치도 대안으로 사용하므로 매번 반드시 다른 위치에 생기는 규칙은 아닙니다.

### 확인 범위

[DailyResourcesMoveDeterministicallyAndRegenerateBelowConsumption](../tests/game_core_tests.cpp)에 재료 수량 복구와 배치 충돌을 검사하는 사례가 있습니다. 이는 설정한 갱신 규칙이 작동하는지 확인하는 근거이며, 재료 압박의 체감이나 난이도가 적절해졌다는 평가 결과는 아닙니다.

## 2. 설치와 회수에 같은 재료 단위 사용

### 의도와 선택

길을 만드는 재료와 파손된 길의 파편을 따로 관리하면 설치, 회수와 보관의 관계가 복잡해질 수 있었습니다. 저는 파편도 같은 길 재료로 취급하고 설치에 2개, 정상 회수에 2개, 파손 회수에 1개를 적용하자고 제안했습니다.

정상 길은 필요한 곳으로 옮길 수 있지만, 파손된 길을 회수하면 재건에 추가 재료가 필요합니다. 하나의 단위 안에서 재배치와 파손의 차이를 표현했습니다.

### 반영된 처리

| 코드 | 반영 내용 |
| --- | --- |
| `kPathBuildCost`와 `PlacePath` | 설치할 때 재료 2개를 차감합니다. |
| `RemovePath` | 정상 길을 회수하면 재료 2개를 돌려줍니다. |
| `RecoverBrokenPath` | 파손된 길을 회수하면 재료 1개를 돌려줍니다. |
| `kPathCacheUnits`와 `CollectResource` | 재료 더미 하나는 길 재료 20개로 계산합니다. |

구현은 [game_core.cpp](../src/game_core.cpp), 회수량 검사는 [RemoveAndRepairUseInventory, BrokenPathRecoveryReturnsOnePathMaterialUnit](../tests/game_core_tests.cpp)에서 확인할 수 있습니다.

## 본인과 AI의 작업 구분

| 구분 | 수행한 일 |
| --- | --- |
| 본인 | 탐사를 이어 갈 기회가 필요하다는 방향, 권역별 부족분 보충, 재료 단위 통합과 설치 및 회수 수량을 결정했습니다. |
| Codex | 전달한 조건을 설계 문서와 코드로 구체화하고, 자원 갱신과 설치 및 회수 처리를 수정하며 테스트를 작성했습니다. |
| 이번 공개본 점검 | 기존 소스와 공개본의 일치를 대조하고, 포함한 소스로 빌드와 자동 검사를 실행했습니다. 세부 결과는 검증 기록에 남깁니다. |

재미의 향상 수치나 사용자 반응을 측정한 자료는 없습니다. 후속 관측 목표는 설계 논의 단계이므로 위 구현 범위에 포함하지 않습니다.
