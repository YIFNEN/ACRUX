# ACRUX

자원을 모아 빛의 길을 놓고, 어두운 숲의 탐사 범위를 넓혀 가는 Windows 생존 탐사 게임입니다. 기지에서 뻗어 나간 길로 세 릴레이를 연결하고, 기지에 돌아와 잠드는 것이 기본 목표입니다.

개인 프로젝트이며 C++과 Win32 API로 제작했습니다. 1.44MB 게임 제작을 목표로 시작해, 이미지 데이터를 실행 파일에 포함하고 음악과 효과음을 코드로 합성하는 방식을 사용했습니다. 이 저장소는 현재 작업 중인 프로토타입의 소스와 기획 판단을 정리한 공개본입니다.

## 플레이 방식

1. 기지에서 출발해 식량, 물, 길 재료를 확보합니다.
2. 길을 설치하고 다음 낮의 충전을 거쳐 탐사 경로를 확보합니다.
3. 파손된 길을 수리하거나 회수하면서 릴레이까지 연결합니다.
4. 남은 기지 에너지를 고려해 탐사를 이어 갈지 귀환할지 결정합니다.

| 입력 | 동작 |
| --- | --- |
| 방향키 | 이동하거나 메뉴 항목을 선택합니다. |
| Z | 주변 자원을 줍거나 길을 수리합니다. 기지에서는 메뉴를 엽니다. |
| C | 길 위치를 선택합니다. 다시 누르면 설치하거나 회수합니다. |
| X | 점멸을 사용합니다. 길 배치나 메뉴에서는 취소합니다. |
| Space | 전력이 공급되는 길 위에 멈춰 개인 빛을 충전합니다. |
| Esc | 일시정지하거나 이전 메뉴로 돌아갑니다. |
| F11 | 전체 화면으로 전환합니다. |

## 기획에서 구현으로 연결한 판단

### 길을 다시 확장할 기회

길 재료가 하루에 한 개씩만 보충되는 대신, 새 밤마다 권역별 설정 수량까지 부족분을 채우도록 정했습니다. 전날 많이 수집했다면 그만큼 다시 확보할 기회를 주려는 의도입니다. 배치할 수 있는 위치를 검사하고, 이전 위치와 다른 후보를 우선 사용합니다.

### 파손에 따른 손실

길 재료와 파편을 별도 자원으로 나누지 않고 같은 단위로 다루도록 정했습니다.

| 행동 | 길 재료 변화 |
| --- | --- |
| 한 칸 설치 | 2개 사용 |
| 정상 길 회수 | 2개 반환 |
| 파손 길 회수 | 1개 반환 |

정상 길은 위치를 바꾸는 데 재료 손실이 없지만, 파손된 길을 회수해 다시 설치하려면 재료를 더 확보해야 합니다. 별도 자원을 늘리지 않고 파손의 비용을 표현했습니다.

자세한 의도와 코드 근거는 [게임 규칙을 정한 과정](docs/GAME_DESIGN.md)에 정리했습니다.

## 본인 역할과 AI 활용

저는 만들고 싶은 플레이 경험, 재료 보충 기준, 설치와 회수 수량을 정하고 변경 조건을 구체화했습니다. Codex에는 해당 조건의 코드 반영, 테스트 작성과 문서 정리를 맡겼습니다. 이 저장소에서는 규칙을 결정한 일과 AI가 수행한 구현을 구분해 설명합니다.

이미지 제작에는 생성형 AI와 이미지 변환 작업을 함께 사용했습니다. 포함한 원본 이미지의 제작 경로는 [자산 기록](docs/assets/asset-ledger.csv)에 남겼습니다.

## 빌드와 확인

Windows와 Visual Studio의 C++ 데스크톱 개발 도구, Windows SDK가 필요합니다. 저장소 루트에서 PowerShell로 실행합니다.

```powershell
# 핵심 규칙의 Debug 테스트
& .\scripts\verify-iteration.ps1 -Profile Logic

# Release 게임 빌드와 실행 파일 크기 확인
& .\scripts\verify-iteration.ps1 -Profile Size

# 게임 실행
& .\out\game-release-x86\ACRUX.exe
```

이미지 데이터가 소스에 포함되어 있어 기본 빌드 전에 자산을 다시 생성할 필요는 없습니다. 자세한 환경과 확인 범위는 [빌드 및 검증 기록](docs/VERIFICATION.md)을 참고해 주세요. 자동 검사는 규칙의 동작을 확인하며, 재미나 조작감의 개선을 증명하는 자료로 사용하지 않습니다.

## 공개 범위

현재 소스, 빌드에 필요한 자산, 변환 스크립트와 선별한 기획 설명을 포함했습니다. 개인 지원서, 대화 원문, 임시 결과물과 제출용 압축 파일은 포함하지 않았습니다. 원래 개발 폴더와 Git 설정은 변경하지 않았습니다.

후속 관측 목표처럼 논의만 진행한 기능은 구현 성과로 소개하지 않습니다. 이 저장소의 공개를 공모전 제출 완료나 출시 완료의 근거로 사용하지 않습니다.
